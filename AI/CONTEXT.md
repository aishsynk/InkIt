# InkIt durable context

## Product

- Windows screen-annotation and presentation application, branded as **InkIt**.
- WPF application targeting `net8.0-windows10.0.19041.0`.
- Uses PerMonitorV2 DPI awareness.
- Solution: `ScreenCanvas.slnx`; application project: `src/ScreenCanvas/ScreenCanvas.csproj` (produces `InkIt.exe`).
- Self-contained win-x64 publish output: `artifacts/publish/win-x64/`.
- Production setup installer: `artifacts/installer/InkIt_Setup_v1.0.0.exe`.
- Branding: user-supplied "inkIT" logo. `Assets/InkItLogo.png` / `InkItLogoWhite.png` (wordmark, dark and white ink), `InkItMarkDark.png` / `InkItMarkWhite.png` ("i" with the red dot), `InkItMark.png` and `InkIt.ico` (the "i" mark on an off-white tile, 16-256 px) are generated from the source image with PIL; see DECISIONS 2026-09-26.

## Current UI architecture (design port, 2026-09-25)

- Source design: `C:\Users\Aishw\Downloads\inkit-screencanvas-workbench` (React/Tailwind). Only the InkIt product UI is ported. Its fake Windows title bar, taskbar, Quick Settings and 8-phase dossier are out of scope.
- Theme: `Settings/ThemeManager.cs` sets semantic `Ink.*` brushes (dark slate default, light variant) plus legacy keys (`PanelBrush`, `AccentBrush`, ...). Palette constants: `UI/Theme/Tw.cs`. Consume theme brushes as DynamicResource/`SetResourceReference` so theme switches update live.
- UI is mostly code-built with `UI/Theme/DK.cs` (Text/Plain, Button, Slider, Switch, Check, Kbd, Chip, Columns, TopRule). `Paint` is either a resource key or a fixed brush. Button hover colours come from `Ui.Hover*` attached properties read by the `Ink.Button` template (`UI/Theme/DesignStyles.xaml`).
- Icons: `UI/Controls/LucideIcon` renders `Lucide.<Name>` geometries from `UI/Icons/LucideIcons.xaml`, generated by `tools/lucide/generate_lucide_xaml.py <lucide-react dir> <design src>` (lucide-react 0.546.0, found locally at `C:\Users\Aishw\Downloads\live-trainer-copilot\node_modules\lucide-react`). Add icons via `EXTRA_ICONS` and regenerate. Do not hand-edit the XAML.
- Toolbar (`UI/ToolbarWindow`): logo drag handle, then items in the grouped canonical order (dividers between `ToolbarItemDefinition.Group`s), then expert switches (snap, multi-tool, orientation, customize). Items come from `UI/Toolbar/ToolbarCatalog.cs` (17 design items, and redo/capture/more/collapse hidden by default). Order and visibility persist in `AppSettings.Toolbar.Items`. Drag-to-reorder uses WPF DragDrop. A drag may only start from the button that received the current press.
- Tool click rule (design): clicking the active tool toggles its inspector. Activating Pen or Shape opens its inspector; other tools close it. Board, Colour and More buttons toggle their inspectors.
- `UI/InspectorWindow` is one reusable 288px card with categories pen, shape, color, laser/spotlight, zoom, board, grid, highlighter, text and more. Floating cards (`UI/Toolbar/FloatingCards.cs`) are non-activating and report their chrome via `IChromeHost` for the overlay exclusion zone.
- Modals derive from `UI/ModalHost.cs` (full-monitor backdrop plus card): Capability Centre, Command Palette, Radial menu, Settings (six tabs, saves on change) and Capture preview. `UI/Toast.Show()` is the notification banner.
- Commands: `Commands/CommandRegistry.cs` uses the design IDs (`annot.*`, `shape.*`, `present.*`, `screen.*`, `privacy.*`, `board.*`, `tools.*`) plus InkIt extras. `ToolbarWindow.HandleShortcut` maps in-app shortcuts to command IDs. The overlay forwards keys through `OverlayKeyRouter`.
- Overlay (`Overlay/OverlayWindow*.cs`) layers, bottom to top: board (transparent/white/`#0F141C`/grid), InkCanvas, vector ShapeSurface, guides and selection, laser trail, spotlight, curtain, ChromeSurface (selection action bar, text editor), status pill. Effect pens use `StyledStroke`. Shape maths is in `ShapeGeometry`. Canvas options live in `ToolSettings` and are changed via `IOverlayManager.UpdateOptions`, which persists to `AppSettings.Canvas`/`Presentation`.
- Global hotkeys (`Hotkeys/HotkeyManager.cs`): emergency Alt+Shift+X (protected, throws if unavailable), toggle drawing, undo, clear, snap Ctrl+Shift+G, capture Ctrl+Shift+4, zoom Ctrl+Shift+5, plus Esc while a tool is active. Other conflicts are skipped and reported by toast.
- Settings migration: `AppSettings.MigrateToDesign()` runs once when `DesignVersion < 2`. It resets theme, toolbar position/layout, presentation defaults and favourites.
- Zoom to area (`Overlay/OverlayWindow.ZoomArea.cs`): `ToolbarWindow.ZoomToArea` picks a region (`ICaptureService.SelectRegion`, which waits for the picker to leave the screen with DwmFlush), captures it, and `IOverlayManager.ShowZoomArea` shows it on the monitor that contains it (`ZoomSurface` layer above the board). While zoomed, the overlay stashes the earlier strokes, shapes and history, and restores them on `ExitZoomView`. Cursor, Esc and emergency release exit the zoom. The zoom bar lives in `ChromeSurface`.
- Trainer features (2026-09-26): `Overlay/ShapeRecognizer` + `OverlayWindow.SmartShapes` (smart shapes, arrows from a V, connectors); `OverlayWindow.Pages` (InkPage swap used by numbered pages, PowerPoint slides and .inkit files; `InkFile`; `Capture/PdfWriter`); `OverlayWindow.Focus`; `Presentation/SlideShowWatcher` (FindWindow screenClass + PowerPoint COM); `Recording/ScreenRecorder` + `MicrophoneCapture` + `UI/Toolbar/RecordingBar` (MP4 to Videos\InkIt); `Presentation/MirrorService`; `Support/` (crash log, links, start with Windows, update checker, single instance, inkit:// registration); `UI/Toolbar/NoticeCard` (tour, update notice). `tests/InkIt.Tests` is a package-free console runner (36 checks) run by `.github/workflows/build.yml` and by the release script.
- Unchanged invariants: Esc always ends the active tool; overlays are click-through in Cursor mode; toolbar and floating UI win hit-testing via `IUiExclusionRegionService`; Eyedropper, Blur/Pixelate and Recording stay removed.

## Validation

- Runtime and geometry evidence is recorded in `QA_RESULTS.md` and `walkthrough.md`.
- Release build command: `dotnet build ScreenCanvas.slnx -c Release --no-restore` (0 warnings, 0 errors).
- Self-contained publish command: `dotnet publish src/ScreenCanvas/ScreenCanvas.csproj -c Release -r win-x64 --self-contained true -o artifacts/publish/win-x64`.
- Release: ``pwsh tools/release/Release.ps1`` (from a clean ``main``) publishes the next 0.0.0.N version from ``version.txt`` to https://github.com/aishsynk/InkIt/releases. ``-RetryUpload`` redoes a failed GitHub step. The exe and installer carry the version (``-p:Version``, ``/DMyAppVersion``); ``AppInfo.Version`` shows it in Settings and the tray.
- Installer compile command: `& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" packaging\installer.iss` (outputs `artifacts/installer/InkIt_Setup_v1.0.0.exe`).
- Publish mode: **self-contained win-x64** (no publish profile; the mode is set by the command above). `packaging/installer.iss` packages `artifacts/publish/win-x64\*`. The output includes `coreclr.dll`/`hostfxr.dll` (245 root files plus 13 framework language folders, 466 files in total). Delete the folder before republishing so no stale files remain.
- Performance validation (2026-09-24, published exe, clean startup, 20 s settle, 10 s sample): 216.1 MB working set, 140.9 MB private, 0.00% idle CPU. After a drawing session the same process measured 315.6 MB / 227.1 MB, still at 0.00% CPU (overlay and palette windows are created lazily).
- Dev switches: `--settings <file>` (isolated settings), `--no-global-hotkeys` (run beside another InkIt instance), `--qa-capture` (renders toolbar, each inspector and the Settings Hotkeys tab (dark and light) to `artifacts/screenshots/qa_*.png` with temp settings, then exits). QA must never type text without first confirming the target window has focus; a missed focus once sent keystrokes into another app.
- The development display runs at 125% scaling: UI Automation and SetCursorPos coordinates are physical pixels (32 DIP = 40 px).
- Runtime QA can be driven without human input from PowerShell: UI Automation locates toolbar buttons by automation ID, `SetCursorPos`/`mouse_event` sends input, and GDI `CopyFromScreen` captures screenshots. Palette items are not UIA buttons, so use coordinates relative to the toolbar. Live Zoom (`MagSetFullscreenTransform`) does not appear in GDI screenshots; verify it with `MagGetFullscreenTransform`. Only send input while the user is idle.
