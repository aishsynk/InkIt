# InkIt durable context

## Product

- Windows screen-annotation and presentation application, branded as **InkIt**.
- WPF application targeting `net8.0-windows10.0.19041.0`.
- Uses PerMonitorV2 DPI awareness.
- Solution: `ScreenCanvas.slnx`; application project: `src/ScreenCanvas/ScreenCanvas.csproj` (produces `InkIt.exe`).
- Self-contained win-x64 publish output: `artifacts/publish/win-x64/`.
- Production setup installer: `artifacts/installer/InkIt_Setup_v1.0.0.exe`.
- Application Icon: transparent brush stroke artwork (`src/ScreenCanvas/Assets/InkIt.ico` with 16 to 256px layers).

## Current UI architecture

- Three-tier progressive disclosure model: Core Toolbar → Contextual Options (palettes) → Advanced Capability Centre.
- Toolbar (runtime-verified 2026-09-24) is a compact floating bar (~40 px wide vertical, 28 px hit targets, Fluent icons) with orientation toggle (`Ctrl+Shift+O` or More palette). Top-level controls, in order: Brand/Presenter Hub (drag handle), Cursor, Pen, Highlighter, Shapes, Text, Colour chip, Eraser, Undo, Redo, Clear All, Present (Laser), Spotlight, Zoom, Screenshot, More, Collapse (17 controls). Toolbar buttons expose `AutomationProperties.Name` and `x:Name` automation IDs (e.g. `PenButton`).
- Attached palettes (one reusable `InspectorWindow`, flush beside the toolbar, same top/height in vertical mode):
  - Pen: 4 nib modes, 4 widths, colours. Highlighter: freehand/straight, 4 widths, colours.
  - Shapes: Line, Arrow, Double Arrow, Rectangle, Rounded Rectangle, Ellipse, Step Marker; colours; 4 widths. `ShapeKind` also contains `Diamond`, which has geometry but no UI entry point.
  - Text: Bold/Italic/Underline, 16/22/30/42 pt, colours. Present: Laser, Spotlight, Code Slit, Keys HUD, laser colours. Zoom and Colour palettes.
  - More: Screen canvas / Whiteboard / Blackboard, orientation, Command Palette, Radial Menu, Break Timer, Freeze, Capability Centre, Settings, Exit.
- Undo, Redo and Clear leave an open palette open. Palettes close via the ✕ button, by clicking the same tool again (toggle) or on Esc.
- Removed features (2026-09-19): Eyedropper, Blur/Pixelate, Screen Recording, and 18 diagram `ShapeKind`s (Database, Cloud, Callout, Connector, Star, etc.). There are no toolbar, palette, command, settings or shortcut entry points for them.
- 6 primary teaching colors: Blue `#2563EB`, Red `#E5484D`, Green `#16A34A`, Amber `#F2B705`, Purple `#7C3AED`, Adaptive Neutral (`#0F172A` / `#FFFFFF`), represented by one active color chip orb on the toolbar.
- Presenter capabilities: Sequential Step Markers (1, 2, 3...), code focus slit band (`CodeFocusService`), non-activating keyboard visualizer HUD (`KeyVisualizerService`).
- Advanced hubs:
  - Capability Centre (`CapabilityCentreWindow`): 46 commands across 7 categories (Annotate, Shapes, Present, Screen, Privacy, Board, Tools). Categories come from the `CapabilityCategory` enum.
  - Settings window sections are generated by reflection over `AppSettings` properties, so any property added there becomes a visible section.
  - Command Palette (`CommandPaletteWindow`): `Ctrl+Shift+P` / `Ctrl+K` keyboard-first command launcher.
  - Radial Quick Menu (`RadialMenuWindow`): circular HUD around cursor.
- Interaction contract: `ANY TOOL → ESC → CURSOR → CLICK-THROUGH IMMEDIATELY ACTIVE`. Overlays are `WS_EX_TRANSPARENT` in Cursor mode. A single Esc (global hotkey in `App.xaml.cs`, and `PreviewKeyDown` on the toolbar and palette) calls `EndCurrentTool`, which also closes any open palette.
- Drawing tools are sticky: one click on another tool switches directly, with no Esc or Cursor step in between.
- Toolbar click handlers must set the tool directly rather than executing a registry command that also calls `onInspectCategory`, because that re-enters the handler and toggles the palette shut (this was fixed for Present on 2026-09-24).
- Input priority: `IUiExclusionRegionService` with `WM_NCHITTEST` `HTTRANSPARENT` pass-through ensures toolbar and floating inspectors always have higher priority than the transparent overlay, enabling direct 1-click tool switching without Esc.

## Validation

- Runtime and geometry evidence is recorded in `QA_RESULTS.md` and `walkthrough.md`.
- Release build command: `dotnet build ScreenCanvas.slnx -c Release --no-restore` (0 warnings, 0 errors).
- Self-contained publish command: `dotnet publish src/ScreenCanvas/ScreenCanvas.csproj -c Release -r win-x64 --self-contained true -o artifacts/publish/win-x64`.
- Installer compile command: `& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" packaging\installer.iss` (outputs `artifacts/installer/InkIt_Setup_v1.0.0.exe`).
- Publish mode: **self-contained win-x64** (no publish profile; the mode is set by the command above). `packaging/installer.iss` packages `artifacts/publish/win-x64\*`. The output includes `coreclr.dll`/`hostfxr.dll` (~258 files). Delete the folder before republishing so no stale files remain.
- Performance validation (2026-09-24, published exe, clean startup, 20 s settle, 10 s sample): 216.1 MB working set, 140.9 MB private, 0.00% idle CPU. After a drawing session the same process measured 315.6 MB / 227.1 MB, still at 0.00% CPU (overlay and palette windows are created lazily).
- Runtime QA can be driven without human input from PowerShell: UI Automation locates toolbar buttons by automation ID, `SetCursorPos`/`mouse_event` sends input, and GDI `CopyFromScreen` captures screenshots. Palette items are not UIA buttons, so use coordinates relative to the toolbar. Live Zoom (`MagSetFullscreenTransform`) does not appear in GDI screenshots; verify it with `MagGetFullscreenTransform`. Only send input while the user is idle.
